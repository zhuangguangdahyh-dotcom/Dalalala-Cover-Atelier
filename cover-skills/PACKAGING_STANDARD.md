# 爆款封面 Skill 封装标准

## 核心单位

每一张经用户提供、逐项拆解并最终验收的爆款参考，对应一个独立的 Cover Skill。不同参考即使看起来相近，也先分别建档；只有真实测试证明结构和适用条件相同，才考虑建立同一 Skill 的变体。

Cover Skill 不是坐标模板。它必须保存参考为什么有效、素材要怎样改造，以及不同内容如何在不丢失版式身份的前提下替换。

## 所有 Cover Skill 的变量合同

用户当前确认的可变因素：

- **人物可变**：可替换人物身份、外貌、服装与动作内容，但新人物必须进入模板规定的主体位置、景别、姿态方向和面积区间。
- **文字内容可变**：可替换主标题、副标题、品牌词与辅助信息，但必须服从原模板的行数、层级、文字块形状、对齐方式和面积比例。标题长度不适配时应改写文案，不能改变版式迁就文字。
- **产品可变**：可替换商品、工具、道具或被展示对象，但必须占据原模板对应的产品角色、数量关系、角度、遮挡与面积区间。
- **色彩搭配可变**：可以按品牌、主题和素材重新配色，但必须保持原模板的明暗结构、冷暖角色、对比强度和颜色面积关系。

用户当前确认的不可变因素：

- **排版不可变**：构图骨架、主体区、文字区、产品区、对齐、层级、阅读路径、前后关系和画面重心必须保持。
- **内容画面占比不可变**：人物、产品、文字、背景及装饰在画面中的相对面积与视觉重量必须落在规则允许的窄区间内。
- **特殊效果不可变**：原模板赖以成立的抠图方式、透视、遮挡、材质、光影、重复、描边、贴纸、三维感或其他特效必须保留其类型、强度层级与作用位置。

这套变量合同高于单个 Cover Skill。每个 Skill 只能进一步收紧范围，不能把不可变因素改成自由生成项。

## 行业语义转换

复刻测试必须使用与原参考不同、但内部逻辑完整的新主题，禁止只改几个名词或继续沿用原参考的行业叙事。

调用 Cover Skill 时，先判断：用户所处行业、账号身份、当前主题、需要展示的对象，以及周围内容在商业表达中承担什么角色。再把模板中的抽象内容槽位转换为该行业可识别的具体形象。

例如：

- AI 行业：不同 AI 工具、能力代理或工作流程角色。
- 宠物行业：不同猫狗、宠物用品、护理环节或宠物性格角色。
- 读书博主：书籍、作者类型、阅读场景、知识主题或拟人书本角色。
- 产品经理：正在推荐、比较或售卖的产品，以及对应用户、功能与使用场景。
- 美妆行业：产品、肤质问题、使用步骤或妆容角色。
- 餐饮行业：菜品、食材、制作环节、地域风味或顾客场景。

形象转换必须围绕同一个主题成立。禁止不分析行业就默认生成通用彩色小人，也禁止只把参考角色换颜色。

## 单张参考的处理流程

1. **原图归档**：保存未经修改的参考图、来源信息与画幅。
2. **视觉解剖**：标注主体、主标题、副标题、辅助信息、背景、装饰、留白、遮挡、层级和阅读路径。
3. **爆点判断**：指出第一眼钩子、情绪张力、反差、信息承诺和缩略图成立原因。
4. **字体识别**：判断字体是可直接调用、可由现有字体风格生成，还是必须建立独立 Font Skill。
5. **重建语法**：把固定骨架、可变内容、可选装饰和禁止动作写清楚；规定素材需要抠图、扩图、换景、重复、透视或特效的条件。
6. **测试复刻**：先用与参考接近的内容验证结构，再至少用一种不同标题长度或不同素材验证可迁移性。
7. **人工验收**：用户确认视觉质量、模板辨识度和实际可用性后，状态才能变为 `active`。
8. **封装注册**：生成独立 Skill，登记到 `cover-skills/registry.json`，并绑定所需字体 Skill 或已有字体风格 ID。

## Cover Skill 最小结构

```text
skills/dalala-cover-<id>/
├── SKILL.md
├── agents/openai.yaml
├── assets/
│   ├── reference-original.<ext>
│   ├── reference-annotated.<ext>
│   └── approved-test.<ext>
└── references/
    ├── anatomy.json
    ├── adaptation-rules.md
    ├── qa.md
    └── manifest.json
```

只在确有重复机械操作时增加 `scripts/`。不得建立没有实际用途的占位文件。

## manifest 必须记录

- `coverSkillId`、显示名、版本和状态。
- 原始参考与标注参考路径。
- 支持的平台、画幅、标题长度、主体类型和内容情绪。
- 第一视觉焦点、空间骨架、阅读路径和图文关系。
- `locked`、`adaptive`、`optional`、`forbidden` 四类约束。
- `variableContract`：人物、文字、产品、配色如何替换。
- `invariantContract`：排版、内容画面占比、特殊效果的量化或区间要求。
- 素材改造级别与触发条件。
- 主标题、副标题及辅助文字对应的字体依赖。
- 已通过的测试案例、缩略图检查和用户验收记录。

## 字体依赖

Cover Skill 通过 `fontDependencies` 绑定字体能力，每个文字角色分别声明：

```json
{
  "role": "mainTitle",
  "type": "font-style-id",
  "id": "dalala-hollow-show",
  "required": true
}
```

如果现有字体无法复刻参考的字骨、笔触、填充、边缘、排布动作或生命力，则先建立独立 Font Skill：

```text
skills/dalala-font-<id>/
├── SKILL.md
├── agents/openai.yaml
├── assets/
│   └── approved-reference.<ext>
└── references/
    ├── style-rules.md
    ├── generation-prompt.md
    ├── vitality-qa.md
    └── integration.md
```

Font Skill 必须同时注册进 `font-style-rules/registry.json`。Cover Skill 只保存依赖关系，不复制字体规则，避免同一字体被多个封面 Skill 各自改坏。

## 状态门槛

- `intake`：只收到参考图。
- `studied`：完成解剖，但还没有成功复刻。
- `testing`：正在进行真实内容测试。
- `approved`：用户确认该参考已被准确掌握。
- `active`：已生成并验证 Skill，可供工作台调用。
- `rejected`：用户否定，保留失败原因但不参与推荐。

“生成完成”不等于“掌握完成”。只有 `active` 项可以自动推荐给工作台用户。

## 验收门槛

- 360 px 缩略图中仍能辨认参考的构图身份和主标题。
- 更换内容后仍保留第一焦点、空间重量和阅读路径。
- 背景、人物、标题之间存在参考要求的真实关系，不靠零散装饰假装相似。
- 中文逐字正确，字体风格和排版动作均通过对应字体 QA。
- 不把参考配色锁死；色彩按内容重新分配角色，同时保持参考需要的对比结构。
- 用户未确认前，不得把试作标记为可生产模板。
