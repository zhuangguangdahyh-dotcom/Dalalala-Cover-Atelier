# 003 适配执行规则

本规则仅供拆解确认后的管理员复刻测试，不能自动用于生产。先读取 anatomy.json 与 manifest.json。

1. 收集行业、账号身份、主题事实、两位角色、单一道具、顶部短标题与两行悬念。缺少真正互动素材时返回素材不适配，不生成通用小人补位。
2. 按 anatomy.contentRoles 重建位置、重量、姿态方向、接触和遮挡。先诊断照片再加字：要求两人全身、头部在33–41%H、道具在49–66%W/42–55%H、背景有真实纵深、地面承接底部文案。
3. 原照满足时用 T0；需补背景用 T2；跨照片用 T1/T2 并统一尺度、光向与地面。人脸、产品结构、事实地点和真实行为是锚点，不能生成假的实测证明。
4. 顶部 5–7 个等效字，底部固定两行短句（3字 / 3字加标点优先）。严格保留上方横向大字及右下阶梯，标题过长先改写；禁止扩区、加行、缩成小字。
5. 通过 fontDependencies 读取字体注册表、各自 style.json、generation-prompt.md 与来源图。这里不复制字形生成规则。测试字体尚未批准，只可明确以测试模式调用。透明文字层通过字形 QA 后再按字效图层合成。
6. 色彩按 64/22/7/3/4 的环境/暗主体/浅字/冷道具/暖末句预算起试，容许小幅偏差；保持强调面积总和5–9%，不锁具体HEX。原色不是所有行业的默认品牌色。
7. 必须保留 layoutContract.locked 与 invariantContract；只改 adaptive。optional 仅允许清理不承载事实的杂物，不添加独立图形模块。
8. 跨行业需要重建同一事件的三角关系：如烘焙师、旁观搭档和单只塌陷蛋糕；宠物主人、护理师和一只宠物；评测员、体验者和一件设备。环境须有行业依据和纵深，动作须与标题对应。
9. 确认拆解后先做同骨架新主题测试，再用不同标题长度或不同素材做迁移验证。测试必须不同于原图行业；不得只换人名、配色或几个名词。完整示例见 analysis.md 第10项。
10. 做全尺寸、360px、灰度和去文字检查，记录失败与修订。用户最终确认前不得 approved/active，不生成封面名称和前台说明。
