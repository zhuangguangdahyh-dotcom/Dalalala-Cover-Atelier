# 参考封面 062｜逐项拆解（待人工确认）

依据注册表原图 `参考封面图/dalala-cover-062-reference.jpg`，原尺寸 1263 × 1684，恰为 3:4。下述坐标以画布左上为 (0,0)、右下为 (100,100)，是观察后的重建区间，不把拍摄时的像素误当固定行业内容。此阶段只有视觉解剖，尚未复刻或跨内容测试。

## 1. 画布与第一眼结论

画面第一眼先读到左侧两行巨大中文：“我把巴黎 / 做成游戏”。黑色上行、深绿色下行几乎顶满左上；第二眼看右侧人物的脸与向左托举的双手；第三眼顺手势落到左下的低多边形巴黎街景，最后停在前景橙白小车。顶部较小的“GPT-6 Astra × Tripo”是身份与合作方说明，尺寸小于中文，但比一般署名更醒目。爆点来自“把一个真实城市做成游戏”的尺度反差：真人像展示一座可玩微缩城市，字面承诺被下方的三维图像立即证明。

## 2. 内容角色、区域与层级

- **合作/身份行**：`GPT-6 Astra × Tripo`，约 x5–67、y4–9；黑色粗无衬线，单行左对齐，位于一切图像之前。它说明制作能力来源，不承担主标题的情绪。换题时必须是确有关系的品牌、工具或系列名，不能用无意义英文凑版。
- **主标题上行**：`我把巴黎`，约 x4–69、y11–24；实心近黑、极粗的四字组合，单行高度约 13%，视觉权重第一。单字并不等宽、同角；上部平切与小斜切相混，字间贴近但字腔仍可辨。
- **主标题下行**：`做成游戏`，约 x4–67、y25–40；实心深绿、同家族巨字，体量与上行接近，单行高度约 13–14%，两行净距约 1–2% 画高。下行绿色把“结果”从上行黑色动作中分出来。文字区占左侧约 2/3，绝不因换词侵入右侧人物脸。
- **副标题与辅助信息**：原图没有另设副标题、角标、页码或底部署名；顶部合作/身份行是唯一辅助文字。迁移时不要为了填空添加解释段落。
- **真人主体**：戴浅色渔夫帽、眼镜、白 T 恤的男性，人物整体约 x30–100、y16–78；脸与帽约 x65–96、y16–44，躯干靠右缘，底部被城市景层挡住。人物是“创作者/讲述者”而不是旅游场景中的游客。左侧上托手约 x30–54、y47–65，另一手约 x46–78、y60–75，双手形成向左下展开的展示框，脸与手不能被标题盖住。脸为第二视觉焦点。
- **三维场景主体**：埃菲尔铁塔约 x3–35、y43–82，是城市识别锚点；从塔底延伸的低多边形河岸、楼群、桥、水、树和路面从 y65 铺到画布底部。场景向远处逐级变小，左塔与右人物在画面中形成“作品—作者”的关系。原图中塔顶进入大块白色留白，增强景物的可触感。
- **前景道具**：橙白小车约 x19–65、y81–99，横向车身压在道路与绿地前方；它让“游戏”从静态城市模型变成可玩的场景。车不属于装饰性贴纸，必须与场景地面有透视、接触阴影与合理尺寸。
- **背景/辅助装饰**：上方约 y0–65 是纯净偏暖白背景，没有标签、箭头、边框或颗粒纸。下方 3D 场景本身提供颜色与细节。树林重复、桥洞重复是场景深度节奏；不再叠加独立贴纸。

## 3. 视觉重心、主轴、阅读路径、留白

主轴不是居中对称，而是左上大字与右上真人对衡，再由人物双手向左下导向模型。上方的水平字行与下方的斜向手势组成两段阅读路径：**身份行 → 黑色动作词 → 绿色结果词 → 人物脸 → 托举双手 → 塔与城市 → 前景小车**。黑绿标题约承担全图 25–30% 的第一眼视觉重量；人物约 25–30%；游戏城市与汽车约 35–40%；其余由白底与空隙消化。上方 x68–100、y3–15 与标题下缘至塔顶之间的空隙要保留，不以小字填满。标题与人物间最窄处留约 2–4% 画宽净隙；人物帽沿可向标题旁接近，但不挡字。

## 4. 素材改造、透视与图层

原图明显是至少三类来源的合成：干净真人抠图、白底文字、3D 游戏城市。真人以中近景裁切，右侧和底部出画，帽沿及手指边缘需精细去底色；左右双手的指向与托举姿势是内容关系，不能用直立证件照替换。城市不是一张矩形风景照：上缘在 y64–74 有楼、树、塔的高低起伏，前景在 y81–100 用车与路面铺满，形成不规则抠边。塔、楼、桥、车须共享同一个游戏化尺度和透视；真实摄影塔、平面贴纸车和低模背景混搭会失效。参考的三维物体是略俯视、近大远小：塔在中景从底部抬起；车在近景明显更大；远方树和桥重复缩小。不要把塔解释成漂浮在掌心的玩具：手势是展示方向，人物与塔之间保留白底间隔。

推荐图层自后向前：暖白纯底 → 远景楼群/天空留白 → 河桥与重复树列 → 中景塔及绿地 → 人物去背层（手臂可局部压在景物之上）→ 道路与汽车前景 → 顶部身份行和两行主标题。合成时允许对人物前臂与局部城市进行分层蒙版，让手自然压过景观而树/路又在人物身前收边；禁止出现硬矩形拼贴边。前景汽车要保留车轮接地，不悬浮。

## 5. 字体骨架与字效

中文不是普通粗黑体的整体倾斜。每字有近方形超重黑体骨架，横竖笔画厚、字腔小但不堵死；外轮廓多处不规则斜切、阶梯状凹凸和少量被“掰动”的边，个别字略向左右扭转。上行四字、下行四字各自连成近满宽的密排块，横向字间约为字宽的 -3% 至 +1%，单字旋转控制在约 ±4°；不得把每字都扭成同一角度。视觉上是像纸块切出来的活字，仍要逐字准确。无描边、无发光、无投影、无三维挤出；黑与绿由两个整行色彩角色区分。现有的普通黑体、描边综艺体、旧纸磨损字、柔软圆字都不能准确保留其厚重字骨与切角节奏，因此建立本模板专属测试态字体 Skill `dalala-cover-062-jagged-block`。字体未经复刻验收，不能当成已批准风格。顶部拉丁字则是标准粗无衬线，字母直立、字距略紧，无独立花字效果；以模板专属测试态 `dalala-cover-062-upright-latin-sans` 记录其身份行排布和逐字准确要求。

## 6. 色彩、面积、材质与光影

参考以明亮中性白作大底（含上部留白约 40–45%），主标题黑约 8–11%，下行深绿约 7–10%，浅色人物约 18–23%，多彩低模场景与车辆约 27–33% 的可见面积共同建立层级；这些是**角色和视觉面积**估计，遮挡区域不要求相加等于 100%。黑字提供最高亮度反差，深绿字把结果词与下方绿地接起来；橙暖塔/车是少量高饱和识别点，蓝绿水面与树群支撑场景。迁移时可改具体色值，但必须保留“浅亮背景 + 两级深色巨字 + 小面积暖色地标/前景物 + 有冷暖分区的三维场景”。用色前按新主体衣服和品牌调整角色，不固定巴黎的绿、橙、蓝。

人物采用明亮柔光，白衣与白底靠自然灰度和局部边缘分开，面部无硬阴影。3D 部分为低多边形、干净的游戏渲染，树冠有明确几何切面，建筑/车有受光面和柔和接触阴影，河水略有光泽；不是胶片纸纹、喷漆、金属字或霓虹特效。车和塔与场景中的树、道路共享一个光向，避免“各图自己发光”。

## 7. 为什么成立、适用内容与素材条件

“我做了什么”用上行提动作，“做成什么”用下行给结果；下方场景把夸张的文字兑现，真人手势又把结果归因于操作者。它适合**人物亲自展示一个可视化成果**的内容：AI 把平面内容变成交互场景、设计师把方案变成空间模型、教师把知识做成可玩的模型、品牌把产品逻辑做成演示场景等。须有可信的人物肖像与双手展示动作，以及一个能在三维/插画化场景中被识别的成果对象；没有成果物时不能靠随机游戏城市场景填充。标题宜两行，各 3–5 个汉字，参考为 4+4；上行负责动作或对象，下行负责结果。若行业名称长，先改写文案，不缩小至普通标题字号，不增第三行。顶部身份行宜一行约 12–22 个拉丁字符或等效短中文，放不下应简写或删掉非必要词。

## 8. 跨行业转换与变量合同

先确定行业、账号身份、主题与展示对象，再找到行业可识别的“地标/成果场景”和“前景交互物”。例如建筑设计师可展示成品微缩街区与一件可辨的使用物；餐饮品牌可展示游戏化餐厅内部与一盘标志菜；宠物服务可展示游戏化护理场景与宠物用品。所有替换都服务同一个主题，人物手势所指必须是实际要展示的成果。人物身份、具体产品/车、文字和色值可换；脸部位置、手势动线、两行字块、人物与场景的面积关系、低模空间深度、前景锚点和明暗结构要锁定。保留“真人与虚拟世界相遇”的特殊效果，不把人物也改成通用卡通小人。

素材检查：人物须有可抠图的头帽/发际、手指与前臂，脸在 360 px 缩略图仍能认出；缺少展示手势时应重拍或重建姿态。成果场景须有清晰地标和近中远景，前景交互物须能正确接地。素材身份/事实锚点保留原貌；城市/背景作为构图自由区重建。没有素材时记为待补，不可声称已经完成复刻。

## 9. 失败模式与验收检查

1. 把图做成“左大字右头像，下方随便一张风景”会丢失手势与成果的因果关系。
2. 标题改成规则黑体加粗、统一倾斜或描边阴影，会失去参考的切角活字身份；必须使用测试字体并逐字校对。
3. 字数超出导致压脸、标题变三行或缩到半号，判为版式失败；先改写。
4. 真人、塔、车互相没有透视/阴影关系，或者城市变真实照片/平面拼贴，判为材质和空间失败。
5. 场景高饱和铺满上半部、白色呼吸区被花字/贴纸侵占、前景物与塔同大小，判为视觉层级失败。
6. 在 360 px 缩略图检查：两行标题先于面孔被读到，面孔与双手可辨，左下成果地标和底部交互物可识别；遮住原文后仍能辨认“左字右人下方游戏世界”的骨架。
7. 中文逐字准确，顶部身份真实，人物身份和产品结构可信；用户确认拆解、近题复刻、跨行业新主题测试与最终验收前，状态保持 `studied`，不得上架。
