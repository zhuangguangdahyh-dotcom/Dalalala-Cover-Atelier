# 参考 008｜内容适配语法（待确认）

## 输入与语义映射

输入必须包含行业、账号身份、受众、一个具体问题、可被短句承诺的结果，以及一件可在右前景举到镜头前的证据物。将原图文字的**角色**而非原词迁移：右上三行是“谁 → 少受什么阻力/获得什么便利 → 在什么场景”，底部两行是“短方法/时间尺度 → 明确对象或结果”，右中一句像本人看到证据时的即时反应。三处文字必须说同一件事；旁白可弱化，不能承担解释整套方法的任务。

## 固定骨架

- 3:4 竖版，左侧贴脸近景；双眼落在 `y=25%–31%`。发顶/左肩出框，脸不能变成全身人像。
- 右前景约 `x=63%–100%, y=32%–80%` 斜举手机或同等证据物；其透视、手指与展示面连续，展示面承担可见事实。脸和手持物在上中部形成暖/冷、近/更近的对照。
- 右上窄区三行细字落在 `x=75%–100%, y=1%–35%`，占用干净底；中行用小面积强调色，首尾高明度中性色。右中 `y≈55%–61%` 一行细笔旁白横跨物件边缘。
- 底部第一行 `x≈5%–73%, y≈66%–80%`，第二行 `x≈2%–99%, y≈80%–99%`，第二行字高约第一行的 `1.25–1.45` 倍。大字有向右下的冷色硬错位背影，不能只用模糊投影或全周描边。
- 眼睛、鼻梁、屏幕中心是保护区。右上保留轻墙面/干净场景留白，不另加卡片、贴纸和大色块。

## 可变范围与动作触发

- **人物**：换身份、年龄、穿着、表情细节可以；保持真实自拍、眼神交流、左大脸的视觉重量。若人脸或身份需要严格一致，先做身份锁定。
- **证据物**：旅行手机可换为产品、书、记录、工具或另一个显示界面；替代物仍要有右前景的大面积、斜向手持、明确展示面与可信透视。只换物件贴图而不处理手与光线，是失败。
- **文字**：内容可变，角色、三行短钩子、一行小旁白、底部两行且第二行最大不变。优先改写长文案；不允许扩宽右上到脸上或把主标题变成三行。
- **颜色**：具体色值可变；保留暖/中性照片大底、高明度主字、一块冷亮证据面及同色系小面积强调/错位边。若证据物不发光，也需以材质明度或局部冷色使其从右侧背景中分离。
- **T0 原貌**：原素材已是左脸右持物同框，且右上有干净区，只做裁切、曝光与文字。
- **T1 空间重排**：同一组素材可通过扩图、轻微裁切或局部清理腾出右上三行与底部两行；脸和物件不变形。
- **T2 结构改造**：人物与证据来自不同照片时，需重建手的握持、机身透视、光线和玻璃反射，经过真实性 QA；不能把矩形界面悬浮贴到脸旁。
- **T3 不适配**：主题没有可见物证、素材只有多人合照或纯文字图、身份真实性无法维持，先换模板或补拍，不强做。

## 图层和字体依赖

照片背景与衣服 → 人脸、手和右前景证据物 → 右上三行 `fine` 透明字 → 右中 `fine` 旁白 → 主标题的硬错位背影 → 主标题 `display` 奶白透明字。`fine`、`display` 均指 `font-style-rules/registry.json` 中测试态 `dalala-cover-008-casual-hand`；字形与排版分开控制，封面 Skill 不复制字体字骨规则。主字影层偏移约 `+0.6%–1.2%W / +0.4%–0.9%H`，边清晰，不打全局光晕。

## 跨行业测试与失败模式

测试须换一个与旅行规划不同且有完整内容逻辑的主题，如真实宠物护理记录、读书笔记过程或软件操作流程。保留同框人/证据的功能关系，再测试短标题和稍长但可改写标题两种情况。不得只把原图名词替换。失败标志：人脸缩小、眼睛被字压住、右上不再有干净底、展示物小成道具、屏幕和手不连贯、蓝边变成全周描边、第二行不再近满宽、细字变装饰噪声、主标题字形错、照片像塑料 AI 合成。测试与用户验收前不得给生产调用标记。
